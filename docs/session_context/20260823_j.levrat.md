## Key Constraints & Patterns
- **Article I.1** — server-side authorization + family isolation. The shopping slice was verified **semantically**: 13/13 new SQL statements genuinely filter by `family_id`; cross-family refusals are byte-identical to "does not exist".
- **Decided conflict semantics (do not reopen)** — LWW on server-stamped `updated_at`; check/uncheck **idempotent**; **delete-wins**; optimistic UI client-side; **no `If-Match`** (OCC was explicitly rejected).
- **Idempotence is implemented as a conditional UPDATE + fetch-on-noop**, never `COALESCE`: a `COALESCE` update moves `updated_at` on replay, which under LWW lets a replayed check beat a concurrent uncheck.
- **State as timestamps, not booleans**: `checked_at`, `archived_at`, `checked_by`.
- **Module boundary is lint-enforced and enumerates business modules by name** — a new module must be added to the group in `backend/eslint.config.js` (this bit us: `shopping/` was missing).
- **Offline-ready without offline**: every list/item payload exposes `updated_at`; every mutation is idempotent-or-LWW.

### New findings — NOT fixed
**Tier 1 — structural**
- **Verification tasks are under-scored by the rubric.** Task 8.1 ("verify the stack runs") scored **2/10 SIMPLE** and ended up adding a **CORS policy to the HTTP server** — a security surface. The auth/security trigger cannot fire on scope you don't know yet. A verification-class task deserves a floor, or a post-hoc re-score note. *(Recorded in the #2 job audit §1.)*
- **"Verified against the live API from Node" ≠ "verified from a browser."** Slice 2 tested the client's own modules from Node, where CORS does not exist — the API was unreachable from any browser and nobody knew. Any web client makes this failure class predictable; it belongs in a `project-guardrails` hint.
- **Module-boundary rules that enumerate modules by name rot silently.** A new business module is invisible to the rule until someone remembers to add it. The rule should be inverted (deny-by-default) or generated.

**Tier 2 — friction (carried)**
- Post-flight constitution verification still cannot run on a derive-generated manifest (document-only predicates) — now hit on **two** consecutive slices. The `code_verification` block exists in the schema; nobody has authored one yet.
- `docs/session_context/` was gitignored for ~60 s and re-tracked (`40914a6`) — **memory and handoffs do not travel between machines**; only the repo does. Auto-memory (`~/.claude/projects/…/memory/`) was empty on this machine after a week of work elsewhere.

### Verification lesson worth keeping
The shopping slice's `-x` pass found the eslint gap by **running a deliberate violation**, not by reading the config. Reading it would have shown a rule that "looks right" — the rule *is* right, it just did not cover the new module. Only execution distinguishes those.
