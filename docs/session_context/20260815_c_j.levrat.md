## Findings from this session

### Fixed and merged to `~/.claude/skills` main (`587e0c6`) — **local only, NOT pushed**
- **Post-flight constitution verification was structurally dead on every project.** Not "this manifest
  lacks predicates" but a **four-way producer/consumer contract mismatch**:

  | | `orchestrate-constitution` emits | `issue-orchestrator` Phase 8 reads |
  |---|---|---|
  | JSON path | `articles[].sections[].verification.must_satisfy[]` | `articles[].verification.code_must_contain` |
  | Vocabulary | `citation`, `text-presence`, `scope-tag` | `code_must_contain`, `code_must_not_contain` |
  | Target | documents (`spec.md`, …) | the git diff |
  | `severity` | never emitted | read, to drive escalation |

  Phase 8's own gate ("skip articles with no code predicate") is therefore **universally true**, so the
  phase self-skipped 100% of the time, silently. The producer's 3-type vocabulary is a *deliberate*
  scoping decision in its changelog; the consumer was written against a vocabulary it never spoke, and
  nothing validates the manifest consumer-side.
  **Fix D** — three gate outcomes, only one silent; `no-code-predicates` now reports
  `⚠ DID NOT RUN — compliance unverified against code` through the audit, gate, and a **new PR-body
  sub-block**. **Fix C** — `sections[].code_verification` block (`must_contain`/`must_not_contain`/
  `severity`/`authored_against_rule_hash`), human-authored at first implementation, preserved verbatim
  across re-derives (schema invariants 9 and 10).
  **It fired for real on this run** and correctly reported `no-code-predicates`.

### New findings — NOT fixed
**Tier 1 — structural**
- **Nothing verifies what the environment CAN already run.** The mirror of the existing "nothing verifies
  the environment can run what it dispatches". A whole session was planned around a Docker blocker that a
  read of `package.json` would have dissolved — `embedded-postgres` was sitting in devDependencies. The
  generalizable rule: *before declaring an environment blocker, read the project's own dependency manifest.*
- **Decisions in a change's `design.md` never reach the constitution.** (Carried from last session, still
  open.) The client run added more: memory-only-token-on-web and no-router-navigation are real, binding
  decisions that live only in `design.md` + a commit message.

**Tier 2 — friction (carried, still open)**
- `jq` default formatting destroys a compact manifest (`step-04a-derive.md` never warns).
- `create-issue`'s Spec Package block prescribes links that are dead in issue bodies.
- `AskUserQuestion` caps at 4 options while `spec-creator`'s scope-tag prompt wants 17.
- `orchestrate-constitution` never links an issue unless `--issue=N` is passed.

### Verification lesson worth keeping
The client passed **typecheck and lint** with a real bug in it: `/auth/login` answers 401 for bad
credentials, and the first cut treated *every* 401 as a rejected session — **a mistyped password signed
the user out.** Only running the client's own modules against the live API exposed it. Static checks
proved nothing about behavior.
