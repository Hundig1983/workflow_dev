`skills/README.md` documented `project-seed` as "ported but not yet wired into anything" — so these

### Open findings — NOT yet fixed
**Tier 2 — structural gaps, every greenfield project hits them**
- **The hand-off void.** `project-seed` ends at "run `/orchestrate-constitution`";
  `orchestrate-constitution` ends at a literal `[mode-specific guidance]` placeholder. The user lands
  with a constitution and no idea what to do next.
- **No bridge from candidate backlog → tickets.** `project-seed` writes `candidate_backlog` into
  `.sdd/handoff/project-seed.json` for *every* project; nothing ever reads it. Conclusion reached after
  debate: this is a **brownfield** concern, not greenfield (greenfield's first pick is self-evident), but
  it is universal and real. Candidate design: bootstrap ~4 **epic issues** (not 15 tickets) via a new
  mode in `create-issue` — not a new skill, and never in `project-seed` (§15 boundary forbids forge).

**Tier 3 — friction**
- **Scope-tag vocabulary is project-contaminated.** The "canonical" 14 tags include `matlab-compat`,
  `parity`, `addon` — residue from the origin project. FamilyHub needed `privacy`, `ai-safety`,
  `tenancy` added via override. Every new project will find the defaults partly irrelevant.
- **Rubric over-scores greenfield.** Foundation tickets score 7–9/10 → RISKY, because the only trigger
  that would correctly read zero ("risk of breaking existing flow") *cannot fire* on an empty repo.
  **Decided: do not fix.** It affects ~1 ticket (the walking skeleton), where the extra rigor is
  warranted anyway. `project-dispatch.md` is the escape hatch if it ever bites.
- **Nobody owns OpenSpec initialization.** `openspec/` appeared as a side effect of installing the CLI;
  no skill claims responsibility for creating it.
- `jq` was missing (installed this session to `~/bin/jq`, v1.8.2, no sudo).

### Key architectural conclusion
The workflow is a **delta processor** — built for change requests against an existing system. Greenfield's
first phase is a **dependency-ordered construction problem**. Rather than harden the workflow for
greenfield, **exit greenfield as fast as possible**: scaffolding is human-owned (no ceremony, consistent
with `project-seed`'s §15 boundary), then **one walking-skeleton ticket** — a thin end-to-end slice —
after which `openspec/specs/` holds real capabilities, deltas become meaningful, and every brownfield
assumption becomes true.
