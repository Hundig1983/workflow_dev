## Findings from this session (the actual deliverable)

### Tier 1 — structural, affects every project

- **Post-flight constitution verification is a structural no-op for Forge-native manifests.**
  `issue-orchestrator` Phase 8 step 5 runs the manifest's `code_must_contain` / `code_must_not_contain`
  regexes against the diff. This manifest — produced by `/orchestrate-constitution` — carries **only**
  `citation` (9) and `text-presence` (9) predicates and **zero** code-level ones. So constitutional
  compliance is **never mechanically verified against code**. The only record is the alignment
  checkboxes, and those are ticked at *spec-authoring* time against the spec's own wording. The
  `{alignment_unticked_count} = 0` the orchestrator reports therefore overstates assurance. Only
  triggers-shape manifests get the real check.
- **Nothing in the pipeline verifies the environment can run what it dispatches.** Triage, complexity
  scoring, guardrails, the claim, and dispatch all completed before anyone discovered there was no
  database and no container runtime. That belongs in a preflight, not 40 minutes into `forge`.
- **`create-issue`'s Spec Package block prescribes links that are dead in issue bodies.**
  `spec-mode-playbook.md` specifies relative links (`../.specs/<slug>/…`) and asserts "GitHub renders it
  if the `.specs/` folder is tracked". That is true in repo markdown and **false in issues** — relative
  links there resolve against the repo URL and 404 regardless of tracking. Worked around here with
  commit-SHA permalinks. Every kiro-mode project ships four broken links on its first issue.

### Tier 2 — friction, reproducible anywhere

- **The scope-tag question does not fit its own tool.** `spec-creator` Phase 3.5.c specifies a 17-item
  checkbox grid; `AskUserQuestion` caps at **4 options**. The vocabulary had to be collapsed into
  curated bundles, which meant reasoning about article intersection *on the user's behalf* — precisely
  the judgment the question exists to elicit from them.
- **The repo's default branch was a spent feature branch.** GitHub had `docs/orchestrate-constitution-2026-08-15`
  as default, so Phase 11 would have targeted a stale branch. **Fixed to `main` this session.** Nothing
  in the workflow checks this; it was caught only because Phase 0 prints the default branch.
- **Label defaults assume a taxonomy greenfield repos lack.** `type:`/`area:`/`prio:` do not exist in a
  fresh GitHub repo. The skill degrades correctly, but every new project starts on the degraded path.
- Minor: `candidates[]` in the manifest uses a different shape from `articles[]` (`topic`/`source_id`, no
  `id`/`title`) — a consumer reusing the article projection renders blanks.

### Confirmed from the previous session
- **Rubric over-scores greenfield** — the walking skeleton scored 9/10 RISKY, with "risk of breaking
  existing flow" the only trigger reading zero, exactly because the repo was empty. The prior "do not

- **Scope-tag vocabulary is project-contaminated** — canonical list still ships `matlab-compat`,
  `parity`, `addon`; this project needed `tenancy`, `privacy`, `ai-safety` as manifest extensions.
